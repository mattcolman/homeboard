# Vision

## A living dashboard for the home

This project is an AI-native household dashboard designed to live in the kitchen on an old iPad.

Instead of navigating a fixed collection of screens, widgets, and menus, a person simply asks for what they need. The dashboard understands the request, finds the relevant household data, and creates an appropriate visual interface in the moment.

Ask it to:

- Visualize this month's spending.
- Show favorite dinner recipes.
- Explain what activities the kids have today.
- Plan the evening around everyone's schedule.
- Combine information from several sources into one useful view.

The result is not primarily a conversational answer. It is a clear, glanceable visual artifact—an HTML page composed for the request, the available data, the device, and the moment.

## What sets Homeboard apart

Three commitments define the product and separate it from smart calendars, dashboard software, and chat-based assistants.

### 1. Voice first

The voice button is front and centre, and it is how anyone asks for just about everything. There is no fixed list of supported questions: Homeboard is also a general-purpose AI, available to anyone standing in front of it. Typing exists, but voice is the primary interface—not an add-on.

### 2. Smart outputs, never a wall of text

For every request, the system decides which output serves the asker best: a spoken answer when words suffice, or a generated visual interface—a custom HTML page composed for the question—when seeing it helps. A wall of chat text is never the output. And when a generated view is worth keeping, it can persist as a widget on the board rather than disappearing when the conversation ends.

### 3. A widget board that grows itself

The board ships with a small set of built-in widgets—calendar, shopping, recipes, chores—and accepts custom widgets created on the fly from a voice request. Custom widgets can use Homeboard's built-in browser to pull live data from websites behind the household's own logins, so the board can show things no public API exposes.

## The central idea

**The dashboard is generated by AI, not merely enhanced by it.**

Traditional dashboards require someone to predict every useful question and design every screen in advance. This dashboard starts with intent instead. AI decides what information matters and how best to present it, then generates the interface live.

Over time, useful views may be cached, reused, personalized, or refined. These optimizations should make the experience faster and more familiar without turning it back into a rigid collection of predefined dashboards.

## A doorway into general-purpose AI

The long-term ambition is broader than a household dashboard. Homeboard should become the household's always-available doorway into general-purpose AI: something anyone can approach with an ordinary question, without first deciding which app, website, or specialist tool to use.

People should be able to ask about the world as naturally as they ask about the household. Homeboard might help someone compare trees for the backyard, understand a school topic, plan a project, troubleshoot a problem, explore an idea, or answer a passing question over breakfast.

The screen makes this more useful than a voice assistant alone. Homeboard can answer immediately in speech, then create the visual support the question deserves: a comparison, diagram, set of options, step-by-step guide, map, checklist, or temporary dashboard. The generated interface is the medium through which AI becomes understandable and actionable, not a limit on what may be asked.

This broader promise can be summarized as:

> Ask anything. Visualize what helps. Act cautiously.

General knowledge should be broadly accessible. Access to private household context should respect who is asking and who can see the screen. Actions with consequences—such as sending a message, changing a calendar, making a purchase, or controlling a device—should require appropriate identity and confirmation.

## Current implementation

Homeboard now opens onto a persistent widget board. Voice and a secondary typed request can create reusable comparisons, explanations, checklists and interactive visuals. Widgets share the same design language and can be kept, moved, resized, refined and reopened without generating them again.

The iPad layout uses 12 columns in landscape, eight in portrait and four on narrow screens. Its reference height is six rows. The board stores each widget's design, data snapshot, interaction state and placement separately, so changing its presentation preserves cooking and checklist progress.

Recipes and shopping lists are functional: saved recipes appear in the Recipes widget, which can also import a recipe from a pasted link, cooking steps persist, and ingredients can be added to shopping. The schedule can use a private iCloud calendar connection, with an encrypted app-specific password and a cached, read-only event view. The shopping list can sync both ways with an iCloud reminder list over the same connection. A weather widget shows the live Open-Meteo forecast for the household's location, derived from request geo. Spending is still labelled as an example; other household account connections remain future work.

Custom interactive visuals run in an isolated frame with a readable fallback. Individual widgets can be explicitly allowed an offline copy for 24 hours. Device performance, microphone interaction and Safari behaviour still need checking on the target iPad before calling this a finished kitchen appliance.

The original fixed-view proof of concept remains available at `?legacy=1` during this transition.

## Experience principles

### Ask, don't navigate

Voice is the natural starting point in a kitchen and the front door to everything Homeboard does. Requests should feel conversational, require little precision, and avoid deep menus or configuration.

### Show, don't just tell

The system chooses the right form for each answer—voice for a quick fact, a generated visual interface for anything worth seeing—and a wall of text is never an acceptable output. Visual responses should favor useful interfaces: charts, schedules, cards, comparisons, checklists, recipes, and other interactive HTML artifacts. Spoken or written explanation supports the interface rather than replacing it.

### Compose around the moment

The same data may need a different presentation depending on the question, time of day, household member, and available screen space. The UI should be generated for the current need.

### Make household data feel unified

Calendars, finances, recipes, lists, and other sources should feel like one coherent household context. People should not need to know which service holds the information they want.

### Be trustworthy at a glance

The dashboard should make it clear what data it used, when that data was last updated, and where uncertainty exists. Sensitive household information must be handled deliberately, especially on a shared screen.

### Improve through reuse

When a generated view proves useful, the system should be able to cache its structure, remember preferences, and update it efficiently. Reuse serves the experience; it does not constrain what can be asked.

### Respect the device and setting

The interface should work well on an older iPad: fast to appear, readable from across the room, touch-friendly, resilient to intermittent connectivity, and uncluttered enough for a shared family space.

## Product promise

Anyone in the household can speak a natural question and, within moments, receive a trustworthy, useful answer and a beautiful view when visualization helps—without first learning where the data lives, which app to open, or how the dashboard works. If the view proves useful, it can stay on the board.

## North-star test

For every product decision, ask:

> Does this help the household express an intent and receive the right visual interface, or does it force them back into navigating software?

As the product expands, also ask:

> Does this make general-purpose AI feel more useful, understandable, and trustworthy in the shared space of a home?
