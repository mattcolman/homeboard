# Homeboard

An AI-native household dashboard designed to live on a kitchen iPad. Instead of navigating fixed screens, you ask for what you need — by voice or text — and Homeboard generates a visual widget for the moment: comparisons, checklists, charts, recipes, schedules.

Generated widgets persist on a responsive board (12 columns landscape, 8 portrait, 4 on narrow screens) and can be kept, moved, resized, refined and reopened without regenerating them.

See `vision.md` for the product vision and `poc-plan.md` for the original plan.

## Features

- **Generated widgets** — voice/typed requests produce trusted React-block compositions (charts, steps, checklists, metrics) or bespoke interactive visuals.
- **iCloud Calendar** — read-only CalDAV connection with an encrypted app-specific password and a cached 45-day event window.
- **iCloud Reminders** — the Shopping widget syncs both ways with a chosen reminder list over the same CalDAV connection.
- **Recipes** — favourites library, persistent cooking progress, shopping list integration.
- **Offline** — per-widget opt-in 24-hour device cache (IndexedDB); service worker caches the app shell only.
- **Legacy mode** — the original fixed-view proof of concept is at `?legacy=1`.

## Architecture

- **Framework:** [vinext](https://www.npmjs.com/package/vinext) — a Vite-based Next.js-compatible App Router (`app/`), deployed as a Cloudflare Worker via `wrangler` and `@cloudflare/vite-plugin`. Hosted on OpenAI Sites (`.openai/hosting.json`, `@openai/sites-vite-plugin`).
- **UI:** React 19 with server components, shadcn/ui (`components/ui/`), Tailwind CSS 4.
- **Database:** Cloudflare D1 (SQLite) via drizzle-orm. Schema in `db/schema.ts`, migrations in `drizzle/` (generated by drizzle-kit from `drizzle.config.ts`).
- **Auth:** requests are scoped to the `oai-authenticated-user-id` header set by the Sites platform. Localhost dev falls back to a fixed local owner. Mutations require a same-origin `Origin` header (`app/lib/widgets/store.ts`).
- **Widget pipeline:** `app/lib/widgets/` — OpenAI generation with a strict JSON schema, validated against bounds; definitions, instances, snapshots, placements and mutation receipts are stored separately for optimistic-concurrency and undo. Untrusted custom code runs in an opaque-origin iframe with a restrictive CSP (`docs/widgets.md` has the full contract).
- **iCloud:** `app/lib/calendar/icloud.ts` — CalDAV discovery limited to `caldav.icloud.com` / `pNN-caldav.icloud.com`, AES-GCM-encrypted credential storage, recurring/all-day event expansion via ical.js.

## Getting started

Requires Node.js >= 22.13.

```sh
npm install
cp .env.example .env.local
```

Fill in `.env.local`:

| Variable | Purpose |
| --- | --- |
| `OPENAI_API_KEY` | Server-side model calls for widget generation |
| `CALENDAR_CREDENTIAL_KEY` | 32 random bytes, base64 — encrypts iCloud credentials at rest (`openssl rand -base64 32`) |
| `HOMEBOARD_WIDGET_MODEL` | Optional model override |
| `HOMEBOARD_IMAGE_MODEL` | Optional image model override (default `gpt-image-2`) for artifact illustrations |
| `HOMEBOARD_IMAGE_QUALITY` | Optional image quality override (default `medium`) |
| `HOMEBOARD_IMAGE_LIMIT` | Max generated illustrations per visual answer (default 2) |

Run the dev server:

```sh
npm run dev
```

Open **http://localhost:3000** directly — not through a proxy or tunnel. Mutation requests enforce a same-origin check, so the browser's `Origin` must match the host the app is served on.

### Database migrations

The local D1 database is created by miniflare under `.wrangler/state/v3/d1/` on first dev run. Pending migrations in `drizzle/` are applied automatically — `npm run dev` runs them via `predev`, and `npm run migrate` runs them standalone. Applied files are tracked in a `homeboard_migrations` table inside the local DB, so reruns only apply what's new.

`drizzle/0007_grey_betty_brant.sql` adds `artifact_images`, which stores the generated illustrations used by visual answers (served from `GET /api/artifacts/images/<id>`).

## Verification

```sh
npm run check    # typecheck + tests
npm test         # tests only
npm run lint     # oxlint (pre-existing baseline warnings)
```

The integration tests run the real route handlers against SQLite with a small D1 adapter and the real migrations. They cover the widget board lifecycle, the CalDAV connection and reminder sync, the push-ingest endpoint, and weather location/forecast handling.
